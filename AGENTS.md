# AGENTS.md — Observer

Репозиторий исследовательский: **кода нет**, только проверенные данные о внешних
системах. Любая будущая реализация — отдельный проект в `D:\GitHub\`.

## Что это

Срез внешних API, инструментов и регуляторных изменений на 2026 год. Хранится
здесь, потому что состояние госреестров, антибот-защиты и цен API меняется
быстрее, чем меняется код.

## Границы отчёта

**Отчёт описывает внешний мир. Утверждения о проектах пользователя в нём
запрещены** — если только они не получены чтением его кода.

Это правило добавлено после двух ошибок первой версии:
1. Утверждение «твои парсеры сломаны, проверь bkr.sudrf.ru» — сделано по
   наличию папки в `D:\GitHub\`. Фактически хост не используется нигде.
2. Раздел о содержимом `knowledge/` — база не читалась, утверждения выведены из
   веб-поиска.

## Правила работы для агента

### 1. Факт или чтение кода — иначе молчи

Прежде чем писать «в твоём проекте X»:
- прочитать соответствующий файл; или
- спросить пользователя.

Наличие папки, имя репозитория и содержимое `README` доказательством не
являются.

### 2. `knowledge/` не читать без явного разрешения

База знаний пользователя. Пока не сказано «посмотри в Знаниях» — не открывать ни
один файл. Это относится и к формулировкам в отчёте: утверждать что-либо о
содержимом базы, не читая её, нельзя.

### 3. Статусы достоверности

| Статус | Значение |
|---|---|
| ✅ проверено | Живой HTTP-запрос или чтение первоисточника сегодня |
| ⚠️ частично | Первоисточник прочитан, но есть расхождения в источниках |
| ❓ не верифицировано | Не удалось проверить |

Всегда указывать дату и, где возможно, конкретный HTTP-код или версию.

### 4. Проверяемость утверждений

Любая цифра в отчёте — измеримая. Если проверка выполнена, указывать чем: живой
запрос, DNS-резолв, чтение первоисточника, поиск по коду. Это отличает факт от
оценки.

### 5. Не переписывай отчёт молча

Правка факта требует:
- новую дату проверки;
- сохранение старой формулировки в истории части;
- различения «проверено» и «выведено».

### 6. Нумерация частей стабильна

`01`…`06` — не переставлять и не объединять без явной команды. Ссылки в
обсуждении — по имени файла, без номеров строк.

### 7. Проекты пользователя не трогать без разрешения

Файлы `D:\GitHub\`, кроме `Observer` — не читать без явного разрешения.
Точечный поиск (`rg`) по запросу пользователя допустим.

### 8. Коммиты

- Прямо в `main`, без веток и PR.
- Сообщение по-русски или по-английски, до 72 символов в заголовке, повелительное
  наклонение.
- Перед коммитом — `git status` и `git diff --stat`.

## Чего не делать

- Не добавлять код без отдельного решения (ADR в `DECISIONS.md`).
- Не создавать новые `.md` без разрешения.
- Не хранить секреты, токены, ключи — даже в примерах.
- Не дублировать `knowledge/` — сначала спросить.
- Не давать рекомендаций по внедрению без проверки состояния проекта.
