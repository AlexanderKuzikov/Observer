# Исследование инструментария — 2026-10-01

Срез внешних API, инструментов и регуляторных изменений, проверенный по
первоисточникам 2026-10-01. Фокус: MCP, SEO и разработка сайтов,
российские госреестры и бухгалтерский контур, стек, обработка документов.

Объём: 6 направлений, каждое — отдельная часть в `docs/research/`.

## Как читать этот отчёт

Это не энциклопедия и не список «лучших инструментов». Это три вещи:

1. **Что сломалось** — изменения 2025–2026, которые ломают уже работающие
   решения. Приоритет высший: это стоит денег прямо сейчас.
2. **Что появилось** — новые возможности и инструменты, которые меняют
   экономику решения.
3. **Что не стоит трогать** — отсев, чтобы не тратить время повторно.

Каждая часть самодостаточна: если интересует только SEO — читать
`docs/research/02-seo.md` и не читать остальное.

## Часть 1. Что сломалось

### 1.1 Скрапинг российских судов — ✅ три хоста мертвы

Проверено живыми запросами 2026-10-01.

| Хост | Симптом | Что это значит |
|---|---|---|
| `kad.arbitr.ru/Kad/SearchInstances` | **HTTP 451** | Не 403. DDoS-Guard с WebAssembly-детектом headless на уровне wasm |
| `bkr.sudrf.ru` | **NXDOMAIN** | Хост удалён. В меню sudrf он всё ещё стоит |
| `bsr.sudrf.ru` | timeout / TLS handshake fail | С российского IP не отвечает. Похоже на фильтр по репутации IP |
| `sudrf.ru` | 200, **windows-1251** | Работает. Кодировка ни при чём — никуда не мигрировали |

**451 — самый дорогой факт.** Не rate-limit, который можно отсидеть, а
`Unavailable For Legal Reasons`: вендор квалифицирует сам факт запроса как
недопустимый. Смена IP по сути не помогает. `ras.arbitr.ru` при этом отвечает
200 — стоит проверить, покрывает ли он нужную задачу.

> **Первое действие:** выяснить, какие хосты реально используют
> `CourtHarvester` и `SudRF-Parser`. Если `bkr.sudrf.ru` — переписывать
> селекторы бессмысленно, хост мёртв. Если `bsr.sudrf.ru` — проблема сетевая,
> а не парсинговая.

Капча на КАДе (`pravocaptcha`) появляется **не на каждый запрос, а после
превышения числа попыток** — блокировка ~3 минуты. Это rate-limit, а не
антибот на каждый запрос. Подробности и рабочий стек — в части 6.

### 1.2 ФНС переписала протокол — ✅

`egrul.nalog.ru/api.php`, `search-rb`, `api-search-rb` — **HTTP 404**. Старый
флоу мёртв целиком. Новый: `POST /` → токен → `search-result/{t}` → poll →
`vyp-request` / `vyp-status` / `vyp-download` (PDF). Капча — числовая картинка,
не SmartCaptcha.

> Код, который ждёт `{"t":...}` сразу в ответе на POST, развалится: нужен
> ещё и поллинг, плюс отдельная трёхшаговая выдача выписки.

**Тихая поломка, ⚠️ самая опасная по стоимости.** ФНС Open Data: наборы
`masaddress` (массовые адреса) и `massleaders` (массовые руководители) **не
обновляются с мая 2021**. Отдаются с HTTP 200. Код, который их читает,
молча работает на пятилетних данных и выдаёт «массовый адрес не найден» как
достоверный вывод. Не диагностируется.

**Живое и бесплатное:** ФНС «Мой ОКВЭД» — публичный API без аутентификации
с 24.03.2026. ⚠️ `POST /tree` работает, `POST /search` отдаёт **HTTP 500**
(серверный баг ФНС, не наш запрос).

### 1.3 ФССП закрыл API — ✅

`api-ip.fssp.gov.ru` → **HTTP 410 Gone**. Живой эндпоинт
`is-go.fssp.gov.ru/ajax_search`, но капча в ответе **всегда**: живая картинка
+ аудио-капча + серверный `code_id` + автообновление каждые 20 с. Самый
сложный антибот в наборе. Либо RuCaptcha, либо отказ от автоматизации.

### 1.4 PyMuPDF — AGPL-3.0 — ✅

Лучший по скорости извлечения текста из PDF, лицензия **AGPL-3.0**. Закрытый
коммерческий продукт без платы Artifex нарушает copyleft. Безопасная связка:
`pikepdf` (MPL-2.0) + `pdfplumber` (MIT) + `pypdf`.

Ещё две мины: `nodriver` — AGPL-3.0. `Camoufox` — MPL-2.0, и его README прямо
пишет «not suitable for stable production use». `MinerU` — Apache-2.0 **с
дополнительными условиями**: при MAU > 100 млн или выручке > $20 млн/мес нужна
отдельная коммерческая лицензия.

### 1.5 `uv` на Windows — дыра в безопасности — ✅

`uv 0.12.18` исправил **path traversal при установке wheel на Windows**
(GHSA-2cv4-cqwr-gwf7). Ниже этой версии — обновить. Актуальная: `0.12.21`.

## Часть 2. Что изменилось и требует решения

### 2.1 У Яндекса нет Core Web Vitals

Раздел «Индекс скорости сайта» в справке Яндекса **закомментирован в
исходнике** — то есть выпилен. Ни LCP, ни INP, ни CLS в ранжировании Яндекса
официально нет. Формулировка Яндекса: скорость «снижает уровень доверия к
сайту, **его посещаемость** и влияет на другие статистические показатели» —
то есть поведенческие факторы, не ranking signal.

Google формулирует мягко, но официально: CWV «aligns with what our core
ranking systems seek to reward». Пороги: LCP ≤ 2,5 с, INP ≤ 200 мс,
CLS ≤ 0,1.

**Практический вывод для работы с клиентами:** под Яндекс нельзя продавать
«LCP ≤ 2,5 с ради ранжирования». Правдивая формулировка — UX, поведенческие
факторы, удержание, конверсия. Под Google — можно.

**Критичное:** INP заменил FID в 2024, и **Lighthouse не умеет мерить INP**
(нет реального пользовательского ввода). В лаборатории — TBT как прокси.

  Вебмастера (Кластер, Конкурентность, Спрос, Клики), бесплатно.

### 2.4 Словостат стал платным

**18.05.2026** — Словостат переехал в Yandex Cloud Search API v2 и стал
платным. Старый `yandex.ru/dev/wordstat/` отдаёт 404.

| Метод | Цена |
|---|---|
| GetTop | 20 ₽ / 1000 |
| GetDynamics | 20 ₽ / 1000 |
| GetRegionsDistribution | 50 ₽ / 1000 |
| getRegionsTree | бесплатно |

1000 фраз в день ≈ **600 ₽/мес**. Номера приходят строками (gRPC int64 →
JSON) — кастовать. В `dynamics` для `PERIOD_MONTHLY` поле `toDate` должно быть
последним днём месяца. `folderId` обязателен, ровно 20 символов.

Потеряно против веб-версии: сравнение нескольких фраз в одном запросе,
«левая/правая колонки», история запросов пользователя.

### 2.9 Спецификация MCP 2026-07-28 — breaking change

Официально: «The biggest changes are breaking ones».

## Часть 4. Сводка по инструментарию

### 4.1 MCP

- Реестр: **131 000+ записей** (❓ нижняя граница, обход упёрся в rate-limit),
  статус **preview**, верификация безопасности **отсутствует**.
- Официальных reference-серверов осталось 7, README прямо говорит «not as
  production-ready solutions». GitHub, Puppeteer, PostgreSQL, SQLite, Redis,
  Sentry, Slack — в архиве, заморожен с 2025-05-28.
- Риски: **CVE-2025-6514** (`mcp-remote`, CVSS 9.6, ~437 000 загрузок) и
  **tool poisoning** — вредоносные инструкции в описаниях инструментов,
  видимые модели, но не пользователю.
- Порог Anthropic: 5 серверов ≈ 55K токенов определений до начала диалога.
  Tool Search режет 77K → 8,7K. Правило: **≤40–50 инструментов в сессии**.
- Российские MCP-вертикали (суды, ФНС, Росреестр, Госуслуги) — **пустота**.
  Единственная глубина — 1С.

Подробно — `docs/research/01-mcp.md`.

### 4.2 Локальные LLM

**6 ГБ VRAM больше не ограничивают размер модели — они ограничивают скорость.**
64 ГБ RAM позволяют держать веса в системной памяти, `-ngl` offload'ит
столько слоёв, сколько влезет.

| Модель | Квант | На этом железе |
|---|---|---|
| **Qwen3.6-35B-A3B** (MoE 35B/3B) | Q4_K_M, ~16,3 GiB | RAM + ~35–40% слоёв в VRAM, 10–18 t/s |
| Qwen3.6-27B (dense) | Q4_K_M | ~50% слоёв в VRAM, 8–14 t/s |
| gpt-oss-20b (MoE 21B/3,6B) | MXFP4 | Влезает в VRAM почти целиком при 4K |

**Спекулятивный декодинг** — 11 реализаций в llama.cpp, комбинируются через
`--spec-type`. Математически не меняет выход модели. `ngram-mod` — ищет
паттерны в собственной истории токенов, идеально для агента-редактора.
`draft-eagle3` — отдельный слой читает hidden states целевой модели.

### 4.3 OCR и речь (русский как критерий)

- **Печатный скан 2000-х**: PaddleOCR 3.7 PP-OCRv5 ru ≥ Tesseract 5.5.3.
- **Таблицы/формулы**: MinerU 4.0.10 (96,33% OmniDocBench) > Docling 2.131.
- **CPU-фолбэк**: RapidOCR 3.9.2 (PaddleOCR-модели в ONNX, без PaddlePaddle).
- **1950-е, машинопись, дореформенная орфография**: ❓ **готового решения нет**,
  нужен собственный дообученный traineddata.
- **Речь, русский**: faster-whisper **large-v3** на CUDA с квантом int8.
  Не turbo — дистилляция под английский.

### 4.4 Доступность из РФ

❓ **Санкционных блокировок инфраструктуры разработки нет.** npm, PyPI,
GitHub, Hugging Face, jsdelivr, Docker Hub — доступны.

Не работает: `ghcr.io`, `sum.golang.org` (нужен `GOSUMDB=off`), TUNA-pypi,
`mirrors.aliyun.com/pypi`. Нестабилен `fonts.gstatic.com` — **шрифты с Google
Fonts рискованно тянуть в прод**.

Работающие зеркала: `registry.npmmirror.com`, `mirrors.cloud.tencent.com/pypi`,
`hf-mirror.com`, `modelscope.cn`, `goproxy.cn`. Ускорения против оригиналов
не дают.

**Вывод: выбор инструментов ограничен лицензиями и качеством, а не
доступностью.** Единственное исключение — облачные OCR API (Mathpix,
ocr.space, Azure Document Intelligence, Google Document AI) с российских карт

## Часть 5. Границы применимости

### 5.1 Юридические границы скрапинга госреестров

**152-ФЗ обычно НЕ применяется** к сбору реквизитов ЮЛ/ИП — это не персональные
данные физлиц. Но ФИО физлица (руководитель, учредитель, ИП) — персональные
данные. Если **обогащать** выписку адресами/телефонами физлиц или
**публиковать связку «ИНН ЮЛ → ФИО физлица»** в открытой базе — становишься
оператором ПДн со всеми обязанностями, включая локализацию в РФ.

Реальные зоны ответственности:

| Риск | Оценка |
|---|---|
| Обход CAPTCHA автоматически | Средний-высокий. Ст. 272 УК РФ, ст. 14.1 КоАП. ФНС и ФССП прямо позиционируют капчу как «подтвердите, что вы не робот» |
| Нагрузка в эффекте DDoS | Высокий. HTTP 451 — сигнал, что вендор считает нагрузку злоупотреблением. 1 запрос в 3 с и 50 rps — разница между нормой и преступлением |
| Публичная перепродажа выгрузки | Высокий |

Информация на сайтах госорганов публична по 149-ФЗ — легальная база для
чтения.

### 5.2 Интегрируется сегодня

ГИС МТ («Честный ЗНАК») — открытый REST, УКЭП, песочница, Swagger для СУЗ.
Образец для подражания: подпись УКЭП в Base64 → токен с TTL 10 часов.

Диадок — самый зрелый коммерческий API: OpenAPI-спецификация, SDK, модуль
для 1С.

1С — легальный путь интеграции без декомпиляции: стандартный интерфейс
**OData** (с 8.3.5, работает и в облаке Фреш) и формат **EnterpriseData**
(94 типа сущностей, XSD выложен). COM/Automation в веб-клиенте и Фреш
**не работает**.

### 5.3 Не интегрируется напрямую

ЕГАИС — публичного REST API нет, только УТМ на своём сервере с
RSA-сертификатом (`FSRAR_ID` в CN). Регулятор переименован: ФСРАР → **ФСКАТР**.

Отчётность в ФНС — через операторов ЭДО. ЕГРЮЛ/ЕГРИП — открытого API нет.
ГИС ЖКХ — есть, но нужен СКЗИ/УКЭП.

## План проработки

Репозиторий создан с расчётом на выборочную работу по частям. Предлагаемый
порядок — от срочного к перспективному:

1. **Часть 3 (юридическая)** — проверить хосты парсеров. Это единственное,
   что горит.
2. **Часть 2 (SEO)** — поднять бесплатный контур. Акцент пользователя
   смещается в разработку сайтов.
3. **Часть 5 (стек)** — быстрые выигрыши: TypeScript 7, ruff, tsdown,
   спекулятивное декодирование.
4. **Часть 6 (документы)** — PyMuPDF и OCR: зависит от решения по п. 2
   открытых вопросов.
5. **Часть 4 (бухгалтерия)** — перспектива, но с самым быстрорастущим
   регуляторным фронтом.
6. **Часть 1 (MCP)** — фоновое, добавлять по мере надобности.
