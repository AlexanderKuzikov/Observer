### Авторизация в ГИС МТ — эталон для подражания

`GET /auth/key` → получаете `uuid` + `data` → `data` подписываете УКЭП
(присоединённая подпись, Base64, лимит 6 МБ) → `POST /auth/simpleSignIn` →
токен, **TTL 10 часов** → `Authorization: Bearer`.

Для СУЗ — отдельный динамический `clientToken` в заголовке, идентификаторы
`omsId`/`omsConnection`, подпись запроса в `X-Signature`. Методы делятся на
«без токена» / приватные. Есть **ролевая модель доступа**.

Документация публикуется **только в PDF** (раздел «Помощь» на промышленном
стенде + Telegram-канал). Для СУЗ — Swagger.

## 8. Что реально интегрируется

### Сегодня, легально и по документации

1. **ГИС МТ («Честный ЗНАК»)** — лучший образец в отрасли. Открытый REST, УКЭП,
   демо-стенды, отдельный контур для интеграторов, Swagger, бесплатный ЭДО
   Лайт. **Первая точка входа**, если делаешь продукт для маркировки.
2. **ВетИС.API** — открытый шлюз с версионированием и тестовым контуром, доступ
   по заявке. Только если ветеринария.
3. **Диадок API** — полноценная документация + OpenAPI + SDK. **Самый зрелый
   коммерческий API** в российском бухгалтерском стеке.
4. **1С OData + EnterpriseData** — работает и в локальной 1С, и в облаке Фреш,
   официально документировано. **Де-факто стандарт интеграции с 1С без
   декомпиляции.**
5. **ФНС Госрегистрация API** — открытый, но по заявке и с УКЭП.
6. **СБП API** — открытый, но документация за JS-авторизацией.

### Не напрямую — только прокси или вручную

- **ЕГАИС** — нет публичного API. Только УТМ на своём сервере + регламентный
  файловый обмен. Фактически локальный SOAP/HTTP-шлюз. Требует RSA-сертификат
  с `FSRAR_ID` в CN.
- **Отчётность в ФНС** — через операторов ЭДО; отдельного «отправь декларацию»
  API нет. **[?]**
- **ЕГРЮЛ/ЕГРИП** — официального открытого API нет, только платные архивы и
  коммерческие прокси (Rusprofile, СПАРК, api-fns.ru, parser-api.com). Практический
  путь — egrul.nalog.ru + капча, что хрупко.
- **ГИС ЖКХ** — есть, но нужен сертификат/СКЗИ.

### Осторожно

- **1С лицензионная чистота.** OData — легальный путь. COM/Automation, парсинг
  файловой БД, декомпиляция конфигураций — серая зона, у 1С есть практика
  претензий к интеграторам. **[?]** — обязательно проверить перед тем, как
  строить продукт, залезающий в чужую 1С.
- **УКЭП везде.** Почти все госсистемы бьут по одной схеме: УКЭП → подпись в
  Base64 → токен. Это можно абстрагировать в одну библиотеку и переиспользовать
  для ГИС МТ, СУЗ, ЕГАИС, МЧД, ЭДО.
