# Часть 5. Стек, локальные LLM, инструменты разработки

Проверено 2026-10-01 по GitHub releases, npm/PyPI registry и официальным docs.

## 1. Локальные LLM

### 1.1 Ключевой сдвиг

**VRAM больше не ограничивает размер модели — ограничивает скорость.** При
64 ГБ RAM веса, не влезающие в 6 ГБ, просто уезжают в системную память, а
`-ngl` offload'ит столько слоёв, сколько влезет. Это принципиально иная
ситуация, чем «купить видеокарту побольше».

| Модель | Тип | Квант | Вес (теор.) | GGUF на диске | На этом железе |
|---|---|---|---|---|---|
| Qwen3.6-27B | dense 27B | Q4_K_M | ~12,6 GiB | ~16–17 ГБ | RAM + ~50% слоёв в VRAM |
| **Qwen3.6-35B-A3B** | MoE 35B / 3B active | Q4_K_M | ~16,3 GiB | ~20–21 ГБ | RAM + ~35–40% слоёв в VRAM. **256 экспертов**, 8 routed + 1 shared active, Gated DeltaNet, Apache-2.0 |
| Qwen3.6-35B-A3B | то же | Q5_K_M | ~20,4 GiB | ~25 ГБ | Качественнее, имеет смысл если Q4 не тянет |
| gpt-oss-20b | MoE 21B / ~3,6B active | MXFP4 (нативный) | ~12 ГБ | есть GGUF | Влезает в VRAM почти целиком при 4K контексте. Apache-2.0 |
| Qwen3-8B-class / Phi-4-mini | dense | Q4/Q5 | 5–6 ГБ | — | Полностью в VRAM, 60–100+ t/s |

**MoE vs dense — важное различие:** у MoE меньше *активных* параметров (быстрее
compute на токен), но **веса всё равно все 35B** — то есть столько же
RAM/VRAM и то же время загрузки с диска по PCIe. При частичном offload на
PCIe-bound сценарии преимущество испаряется, на CPU-bound (ускорение prompt
processing) проявляется. Плюс MoE чувствителен к маршрутизации экспертов:
старые бэкенды читают конфиг, но генерируют неверно.

Источники: `huggingface.co/Qwen/Qwen3.6-35B-A3B` (Apache-2.0, 16.04.2026),
GGUF-конверсии `bartowski/Qwen_Qwen3.6-35B-A3B-GGUF`, методика расчёта VRAM
`knightli.com/en/2026/05/01/qwen3-6-local-vram-quantization-table/`

**Ожидаемые скорости** (оценка по классу железа, не измеренная цифра — замерить
через `llama-bench`):

| Сценарий | Скорость |
|---|---|
| 8B Q4, всё в VRAM | 70–110 t/s |
| 27B Q4, 50% слоёв в VRAM | 8–14 t/s |
| 35B-A3B Q4, ~35% слоёв в VRAM | **10–18 t/s** |
| 35B-A3B Q4, полностью в RAM | 5–8 t/s |

### 1.3 Спекулятивный декодинг

llama.cpp поддерживает **11 реализаций**, комбинируемых через `--spec-type`:

| Тип | Механика | Когда выигрывает | Применимость |
|---|---|---|---|
| `draft-simple` | отдельная маленькая draft-модель (`-md`) | универсально, +1,5–3× при хорошем принятии | **да** — есть EAGLE3-чеки для Qwen3 (1,7B/4B/8B/14B/32B/a3B) |
| `draft-eagle3` | 1-слойный трансформер читает hidden states целевой модели | acceptance выше, чем у standalone draft того же размера | **да, лучший выбор** — готовые `AngelSlim/Qwen3-*_eagle3`, `Tengyunw/qwen3_30b_moe_eagle3`, `RedHatAI/gpt-oss-20b-speculator.eagle3` |
| `draft-mtp` | MTP-головы самой модели, без внешней модели | когда модель их имеет | зависит от Qwen3.6 |
| `ngram-simple` / `ngram-map-k` / `ngram-map-k4v` / `ngram-mod` | поиск паттернов в собственной истории токенов, без модели | **рефакторинг кода, суммаризация, повторяющиеся структуры** | **идеально для агента-редактора** |
| `ngram-cache` | внешняя статистика из файлов | редко | спецслучай |
| `draft-dflash` | block-diffusion, целый блок токенов за forward pass | GPU-friendly драфтинг | только Qwen3-таргеты |
| `draft-dspark` | DFlash + полуавторегрессивная Markov-головa | лучше левой части сигнала | только Qwen3-бэкбоны |

Ключевые флаги:

```bash
--spec-default                      # включает ngram-mod, минимум возни
--spec-type ngram-mod,ngram-map-k4v  # комбинирование реализаций
-md / --model-draft <file.gguf>      # draft-модель
--spec-draft-n-max N                # длина драфта (по умолчанию 3)
--spec-draft-ngl auto|all|N          # сколько слоёв draft в VRAM
--backend-sampling                   # сэмплирование на бэкенде, снимает CPU-оверхед
```

Бенчмарк в комплекте: `tools/server/bench/speed-bench` сравнивает базовый прогон
против спекулятивного end-to-end. Есть «синтетический acceptance»
(`--spec-synth-rates`, `--spec-synth-len`).

**Практический вывод:** Qwen3.6-35B-A3B + EAGLE-3 draft +
`ngram-mod`, замерить через SPEED-Bench. Если acceptance > 0.6 — заметное
ускорение **бесплатно по качеству**: спекулятивный декодинг математически не
меняет выход модели.

Документация: `github.com/ggml-org/llama.cpp/blob/master/docs/speculative.md`

### 1.4 KV-кэш и offload

`--no-kv-offload` как флаг не актуален. Актуально явное управление типами:
`-ctk/-ctv` (`f32`, `f16`, `bf16`, `q8_0`, `q4_0`, `q4_1`, `iq4_nl`, `q5_0`,
`q5_1`). Для 4K контекста на Qwen3.6 KV-кэш в f16 упирается в VRAM — понижение
K-типа до `q8_0` или `q4_1` освобождает десятки мегабайт без заметной потери.

**Не мешать три разные цифры:** теоретический вес (параметры × битность), размер
GGUF-файла, рантайм-потребление (веса + KV + буферы вычислений + mmproj +
overhead). Замерять через лог старта + `nvidia-smi --query-gpu=memory.used`.

Для MoE смотреть в лог число offload-слоёв и распределение экспертов — часть
бэкендов держит MoE-веса в CPU целиком.

### 1.5 Подводный камень для агентного цикла

`chat-template`: разные версии Qwen используют разные шаблоны и thinking-режимы.
Признаки поломки: выводятся литералы `system`/`user`, повторы, невалидный JSON
в tool call. Не лечится удалением спец-токенов — сначала проверить model card и
поддержку бэкенда. Temperature 0,1–0,3 для кодинга.

Практический вывод: **локальная модель — для приватных задач** (документы
заказчика, приватные репозитории), **облако — для всего остального**.

**Exa vs Tavily** (разделение от самих вендоров): **Exa** — когда нужен
retrieval, не являющийся веб-страницей (код, люди, компании, бумаги), и когда
tail latency задаёт таймаут агентного цикла. **Tavily** — когда нужен полный
текст каждого результата и высокий объём общих web-запросов.

Бесплатные альтернативы: DuckDuckGo, SearXNG (self-hosted, без API-ключей),
Brave, Jina, Firecrawl.

  в INP, какая фаза LTP).
- **Speculation Rules API** — предиктивный prefetch/prerender по hover/list.
  **Chromium-only**, по назначению — для **MPA**, не SPA. Главный gotcha:
  prerender расходует ресурс на то, что может не открыться. Начинать с
  консервативных **prefetch**.
- **View Transitions API** — cross-document вариант для MPA работает, opt-in
  через CSS. Хорошо сочетается со Speculation Rules.

| Инструмент | Модель | Скорость | Русский | Оценка |
|---|---|---|---|---|
| **faster-whisper** (CTranslate2) | large-v3, large-v3-turbo | **на CUDA быстрее whisper.cpp в 5–7×** | хороший на large-v3 | **основной рантайм для GPU** |

> **Рекомендация для русского:** **large-v3 (не turbo) + faster-whisper на
> CUDA**, квантование int8. При 6 ГБ VRAM large-v3 в int8_float16 помещается;
> при полном fp16 (~10 ГБ) уйдёт в CPU-offload, что на CUDA медленнее. Turbo
> хорош на английском, но на русском не жертвовать точностью ради скорости.

### Главный риск MCP

MCP-сервер = удалённое выполнение кода агентом. Каждый подключённый сервер
расширяет blast radius. Минимум: явный конфиг, токены, `--read-only`.
